# 中国移动 12.5.5：`CmccApplication.onCreate` 到 DEC 的真实连接

本报告基于原始、SHA-256 固定的 `libdatajar.so`，跨两个可恢复 Dex 片段对照 `method_ids`、方法原型和 `code_item`。所有偏移均为 SO **文件偏移**。

## 关键结论

中国移动原始 `com.mc10086.cmcc.base.CmccApplication` 的 `onCreate()` 方法体执行下面三条指令（位于第二组 Dex）：

```text
SO offset 0x364ae2c
invoke-virtual {v1}, CmccApplication.DEC_origin_onCreate()V

SO offset 0x364ae32
invoke-static {v1}, DECApp.intiDECabcOnCreate(Landroid/app/Application;)V

SO offset 0x364ae38
return-void
```

原始代码的字节内容为：

```text
6e 10 1b ad 01 00
71 10 e3 0c 01 00
0e 00
```

方法本体 `code_item @ 0x364ae1c`，方法 ID **44339**；第一处被调用方法 ID **44315**，第二处为 **3299**，均经本片段的 `method_ids` 验证。

- `CmccApplication` 类型 ID **6791**，`class_def @ 0x30a1908`，父类为 `Landroid/app/Application;`。
- `DECApp` 类型 ID **781**（本片段是方法引用，没有类定义），`intiDECabcOnCreate` 的签名明确为 `void (android.app.Application)`。
- `DEC_origin_onCreate` 的代码实现 `@0x364ab78` 也已找到，共 59 条 16-bit code units。

因此已证明：**原版中国移动的 Application 启动阶段通过插入的调用进入 DEC 检测初始化**。名称 `DEC_origin_onCreate` 是二进制中的原样拼写；它与原 `onCreate()` 的拆分方式可从代码体观察到，但该改写究竟由哪一步打包或加固完成仍有待单独证明。

## 已证实的跨 Dex 调用链

```text
第二组 Dex（SO 相对基址 0x2f0e00c）
CmccApplication.onCreate()V [method 44339]
 ├─ CmccApplication.DEC_origin_onCreate()V [method 44315]
 └─ DECApp.intiDECabcOnCreate(Application)V [method 3299]
            |
            v
第一组 Dex（SO 相对基址 0x500c）
DECApp.intiDECabcOnCreate(Application)V [method 62487]
 ├─ DECApp.isMainProcessDECabc()Z [method 62488]
 │    └─ /proc/<当前 PID>/cmdline 与 getPackageName() 比较
 ├─ 若非主进程：return-void
 ├─ 主进程：registerActivityLifecycleCallbacks(DECApp$1)
 └─ DeviceEnvironmentCheck.startCheck()V [method 62496，SO 0x1c20672]
            |
            v
        实现尚未恢复
```

特别说明：第二组 Dex 的 `method_id 3299` 及第一组 Dex 的 `method_id 62487` 属于**两个独立的索引空间**；它们的方法签名均为 `intiDECabcOnCreate(Application)V`，指向同一个 Java 类与方法。不能简单将不同 Dex 的索引号直接比较。

第一组 Dex 中原先被保护的字符串索引也已回溯得到：`6175="/proc/"`、`6173="/cmdline"`、`17647="Landroid/os/Process;"`、`17422="Landroid/app/Application;"`。因此先前对于读取进程命令行路径的推测，现在有了直接字符串和字节码双重支持。

## 如何复核

```powershell
python .\tools\inspect_cmcc_dec_bridge.py .\path\to\base.apk
```

运行时会验证原版文件哈希、早期字符串索引、Application 父类、方法 ID、原型、调用指令与 SO 偏移。仓库不保存商业 APK 或原始日志。

## 剩余问题

已确定 DEC 初始化确实运行于 App 的 `onCreate` 路径；目前仍缺 `DeviceEnvironmentCheck.startCheck()` 的实现。它有方法引用却没有对应有效 `class_def`，可能位于尚未恢复或运行时保护的其他代码区域。**RootBeer 在另一个片段中的存在不足以证明它就是 DEC 的 Root 判定来源**；应继续查找从 `startCheck` 到检查条件及弹窗的实际调用链。
