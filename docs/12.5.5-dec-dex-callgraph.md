# 12.5.5：从 SecNeo `libdatajar.so` 恢复的 Dex 方法调用链

日期：2026-10-22。样本和版本必须与 [静态取证报告](12.5.5-static-analysis.md) 一致。此处只记录原始二进制中可重复验证的表结构、方法 ID 和调用指令；不将符号名字自动当作检测语义。

## 样本验证

- APK SHA-256：`6282d2cf05f76f37a60fff322bcf0d6f1d876829e5c9c4eae5cdd93b7a972a83`
- `lib/arm64-v8a/libdatajar.so` SHA-256：`8b0777aeeedb1d95041fb8b5a900735d607505f802255227a82c83225d8bbf81`
- 文件字节数：158,739,792；以下偏移均是**SO 文件偏移**，不是 ELF 虚拟地址。

## 发现：保留下来的 Dex 索引与方法定义

扫描 `libdatajar.so` 时，发现 Dex 风格 `string_ids` 表的连续区段；每个 32-bit 小端数值加 `0x500c` 后均指向长度由 ULEB128 编码、以 NUL 结束的字符串数据。对 **64,327 个连续条目**逐一验证了单调偏移与字符串分隔符，不依赖孤立字符串命中。

| 表 | SO 文件起始偏移 | 已校验条目数 |
|---|---:|---:|
| 可见 `string_ids` | `0x2500c` | 64,327 |
| `type_ids` | `0x63d28` | 18,558 |
| `proto_ids` | `0x75f20` | 10,016 |
| `field_ids` | `0x934a0` | 44,330 |
| `method_ids` | `0xe9df0` | 64,884 |
| `class_defs` | `0x168990` | 约 16,526，见局部有效性检查 |

根据 Dex 标准头长度 `0x70` 和推算基址 `0x500c`，`string_ids` 应从 `0x507c` 开始。直到首个可见索引 `0x2500c` 恰相隔 `0x20000`（128 KiB），因此**推算**前 32,740 个字符串索引不可直接读取、总索引数约 97,067。该 128 KiB 区域 Shannon 熵约 **7.99848 bit/byte**；可见字符串索引后续 128 KiB 熵约 **6.4896 bit/byte**。这些特征支持前缀经过加密或其他高熵变换，但未证明具体加密方式或密钥。

`class_defs` 中 `class_idx` 不是严格单调的，不能使用「不升序则结束」的规则判断类定义结束；本文以结构有效性及类索引扫描为依据。

## 已验证的 DEC 调用链

```text
Lcom/a/b/c/DECApp;->onCreate()V
    method_id 62489   code_item @ SO 0x1c207f4
    invoke-static @ SO 0x1c2080a
          |
          v
Lcom/a/b/c/DECApp;->intiDECabcOnCreate(...)
    method_id 62487   code_item @ SO 0x1c205f8
    invoke-static @ SO 0x1c20672
          |
          v
Lcom/a/b/c/DeviceEnvironmentCheck;->startCheck()V
    method_id 62496
    method reference exists; class definition/implementation not recovered
```

两处 `invoke-static` 均有明确的 Dex 35c 编码，操作码 `0x71`；目标方法索引依次为 `62487 (0xf417)` 和 `62496 (0xf420)`，已与 `method_ids` 交叉验证。

此 Dex 中 `DECApp` 的 `type_id=17418`、`class_defs` 文件偏移 `0x1e9770`；其 4 个已知方法为方法 ID 62486–62489。 `DeviceEnvironmentCheck` 的 `type_id=17421`，仅发现 `startCheck` 方法引用，在当前有效 `class_defs` 中没有对应实现。可以肯定此段字节码**调用了** `startCheck()`；具体运行时执行条件、方法体加载位置和检测项仍未知。

此前在偏移 `0x7ec143e` 发现的明文 `getCheckResult` 位于**远离本次恢复片段的其他字符串区域**，目前不能归属给 `DeviceEnvironmentCheck`。这条此前未验证的猜测继续保持未验证状态。

## 边界与下一步

- 仅凭 `DECApp.onCreate` 的调用关系，无法证明主 Application `CmccApplication` 继承了 `DECApp`、或具体在何时调用了它。
- `DeviceEnvironmentCheck.startCheck` 的方法**引用**与方法**定义**需要严格区分；当前没有其方法体，不能证明它检测哪一项 Root / Frida 痕迹。
- `RootBeer` 描述符的已知命中在 SO `0x3b0921f`，属于另一段数据；尚未恢复其在该区段对应的类定义和调用图。
- 下一步优先继续定位其他 Dex 片段与完整 DEC 定义，保持只读原始样本、不修改 APK 或设备。
