# 中国移动 12.5.5：TracerPid 阳性后更新 envc.push 的 root 记录

验证日期：2026-10-24。证据来自用户之前保存的原版 APK（SHA-256 6282d2cf05f76f37a60fff322bcf0d6f1d876829e5c9c4eae5cdd93b7a972a83）及其经完整哈希检验的内层 libDexHelper.so（SHA-256 b0d42eb0d86a7fdd3c4e5669c46376d0d4c041da5adb3f5d0e3ccbe9f369ef54）。原版、解包 ELF、设备隐私材料均未提交。

续接 [双向管道与 TracerPid 检查](12.5.5-secneo-h-pipe-result-chain.md)、[异常分支](12.5.5-secneo-h-result-guard-branch.md)及[配置初始值 13](12.5.5-secneo-h-guard-config-alias.md)。

## 1. 原生调用序列

在前述 TracerPid 数值 >=1、运行时配置对象 +0x17c 的 bit0=1 时，进入 0x5af18：

| 原版内层 ELF VA | 实际数据流 |
| --- | --- |
| 0x5af20 | mov w0,#1，传入记录键的索引 1 |
| 0x5af34 | bl 0x2616c，取出键名字串并复制到调用者缓冲区 |
| 0x5af38 | 如果返回 0，跳至 0x5af6c 清理路径 |
| 0x5af44 | bl 0x2682c，查询该键对应的已有文件记录 |
| 0x5af48–0x5af4c | 测试返回值低字节，非零时跳过更新 |
| 0x5af50–0x5af5c | mov/movk/orr 构造 w2=0xb6a281fb |
| 0x5af60–0x5af64 | x0 指向上述键名缓冲区，w1=1 |
| 0x5af68 | bl 0x26bc0，在前序条件允许时执行记录更新 |

这属于 **有条件的静态可达调用**。是否在具体设备运行时写入成功仍需要独立证据。

## 2. 索引 1 的记录名确实是 root

在函数 0x2616c 中，0x26188/0x2618c 建立内层 ASCII 表指针 0x1240f4+0x41；0x26198、0x261a8、0x261b0、0x261b8 的四次原始 LDRB 读取的字符分别为 r、o、o、t，存入 x29-0x6c 一带的栈缓冲区。

更重要的跳转表：0x265cc 执行 w8=w0-1；输入 w0=1 时索引为 0。位于 0xf0098 的第一个表项实际字节为 1；0x265e0 以 0x265f4 为基址，故跳转到 0x265f8。0x265ec 已将 x1 指向 x29-0x6c 的 root；跳过 0x265f4 的另一条赋值语句。随后 0x26740–0x2674c 把字串复制到传入的输出缓冲区。因此 **索引 1 精确选择 root**。

旁边的确也构造了 usb 字串。它属于别的选择分支；不能仅凭源码中的空间邻近把 usb 误认成索引 1 的结果。

## 3. 查询和更新函数都定位 envc.push

通过原版代码 LDRB 的索引立即数，在已恢复的可打印 ASCII 表中逐字节还原：

- 0x2682c 查询函数：0x268b8–0x26918 对应九个字符，得到 envc.push；0x26930 调用 fopen，模式来自原版只读字串 r；0x269b0 调用 fgets，后续还有 strtoul 等记录解析逻辑。
- 0x26bc0 更新函数：0x26c5c–0x26cc0 的另外九个字符也恢复为 envc.push。0x26cc8 使用原版格式 %s%s 拼接运行时目录前缀及文件名。
- 两者读取的目录前缀来自原版 R_AARCH64_RELATIVE 重定位项 0x123f70，目标地址为 0x128010。这个缓冲区内容受运行时状态控制；**只确认文件名 envc.push，不能据此猜测设备上的绝对路径**。
- 更新函数 0x26d30 先调用 access；在文件缺失时会尝试 fopen("w+") 创建；0x26d5c 使用 fopen("r+")；0x26d70 使用 flock 的 LOCK_EX 选项；读入并处理既有记录之后，0x27130 使用 fseek，0x27144 使用 fwrite，接着调用 fflush/fclose。

同一函数的原版格式串还原为 %s=%x%x。本次调用键 root、整数 1、标识常数 0xb6a281fb，因此 **格式化阶段**得到 root=1b6a281fb。但随后的 0x26e78/0x270ec 及其他内部函数对缓冲区实施了解析和分块变换，**没有证据显示文件最终储存的明文就是这个字符串**。也不能据代码存在 fwrite 推断某次设备一定执行到了写入处。

## 4. 证据含义

已有原版静态链：H.main 使用默认 --flags 0 检查 TracerPid → writeUTF 管道 → 父端 readUTF/atoi → >=1 → +0x17c bit0 守卫 → 0x2616c(1) 选择 root → 0x2682c 查询 envc.push → 返回条件允许时 0x26bc0 更新同文件。

这证明 TracerPid 阳性路径能够进入 **root 标记的本地记录查询/更新机制**。root 是原版编码字符串的事实，它的业务语义以及文件内容由谁消费还没有恢复；不能据此宣布已经证明 Root 检测、DeviceEnvironmentCheck.startCheck()、DECMsgDialog 或先前 SIGSEGV 的具体因果关系。

设备 FD 读取权限被限制这一点已由 Root Shell 自检确认，继续分析应优先复核同一文件的其他消费点，不再重复失败的 FD 采样。

## 6. 同一线程的第二条 root 更新路径及全 ELF 调用面（续查）

原版线程函数后段、与此前的 0x5b344 配置字节 bit0 条件分支连接的 0x5b3c0 起，同样存在一组与前面完全同类型的三次调用：

| 原版 ELF VA | 证据 |
| --- | --- |
| 0x5b344 | tbnz w8,#0,0x5b3c0（bit0=1 时进入） |
| 0x5b3c8 | mov w0,#1，选择同一个 root 键 |
| 0x5b3dc | bl 0x2616c，将键名复制到缓冲区 |
| 0x5b3f0 | bl 0x2682c，查询 envc.push 已有记录 |
| 0x5b3f4–0x5b3f8 | 测试返回值低字节；非零时跳过更新 |
| 0x5b3fc、0x5b408 | 构造 w2=0xb6a281f1 |
| 0x5b404 | w1=1 |
| 0x5b40c | bl 0x26bc0，条件允许时更新 root 记录 |

与前述 0x5af68 路径的参数标识 0xb6a281fb 相比，此处使用 0xb6a281f1，两者相差 0x0a。仅能说明有两处可达原生记录更新路径，暂时不能解读常数的业务类别或实际设备执行归属。

从原始 ELF Section Header 独立确认 .text 地址/文件偏移 0xfa00、大小 0xe0358，在整个节内每 4 字节按真实 AArch64 BL 编码解出目标，而不靠字符串或邻近地址猜测，得到以下静态直接调用点计数：

| 内层 helper | 完整 .text 节中直接 BL 指令数 |
| --- | ---: |
| 0x2616c 短键名选择 | 83 |
| 0x2682c envc.push 查询 | 84 |
| 0x26bc0 envc.push 更新 | 48 |

这是一套**被大量代码复用的原版记录机制**。计数代表可验证的静态直接调用指令，不等于 48 次真实文件写入，也不等于所有调用点都在实际运行时可达。动态间接调用也不在本轮 BL 统计范围内。

配套审计工具现包括对第二组 root 路径的逐字节机器码校验和完整 .text 直接调用点统计；合成测试构造整个同样尺寸的 ELF .text 节，在其中写入独立生成的 BL 指令，检查 83/84/48 计数及丢失单个调用时的拒绝行为。

**后续工作**：先追踪哪些已验证调用点使用具体索引和怎样读取 root 值，再核查其是否与 Java DEC 组件发生真实数据交互。

## 7. 文件读端究竟如何解释记录（进一步原版指令核验）

原始读取函数 0x2682c 内，0x2696c、0x26980、0x26990 三次 LDRB 从原版可打印字符表解出格式串 **%s=**；0x2699c 通过内部安全格式化封装，使用传入键名（本次是 root）构建待匹配的记录前缀 root=。

在已有数据解包、匹配此前缀的条件下，原版 0x26b24–0x26b44 定位到该前缀后一个字符；0x26b50 执行 sub w22,w8,#0x30，将 ASCII 数字字符转为状态值。紧接着 0x26b4c 设置 w2=16（十六进制进位制），0x26b54 调用 strtoul@plt，解析剩余字符串中的十六进制部分。0x26b60 检查是否已消费到字符串结束，满足条件后 0x26b64 将解析结果写入调用者的结果指针；0x26b90 最终以 w22 返回前述状态数字。

由此可把格式化阶段的 root=1b6a281fb 分成三个字段：**root=**（键前缀）、**1**（ASCII 状态数字）、**b6a281fb**（十六进制数值）。读取函数会把这两类数值分别作为返回值和可选输出参数。由于写入前存在内部记录编码/转换，这属于**逻辑记录的解析格式**；设备上实际文件存储的字节结构、该十六进制常数的风险等级语义以及是否由 DEC 消费，仍未得到原版直接证明。

读取结果低字节非零时，0x5af4c 和 0x5b3f8 的两个原版路径都会直接跳过更新，因此具备 **已标记则跳过** 的条件逻辑。这并不保证文件操作在全部故障情况下幂等，读文件失败、数据格式变化及其他调用者还可能改变最终行为。

工具已追加对 %s= 三次字符表读取、状态字符减去 0x30、十六进制进位制、strtoul 及输出缓冲区写入的固定指令核验。下一步应从其他 83/84/48 个直接调用点着手，找出上层消费这个状态的确切路径。
