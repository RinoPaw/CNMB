# 中国移动 12.5.5：TracerPid 阳性分支通向条件文件修改代码

核验日期：2026-10-24。原版 APK SHA-256 为 `6282d2cf05f76f37a60fff322bcf0d6f1d876829e5c9c4eae5cdd93b7a972a83`；内层 `libDexHelper.so` SHA-256 为 `b0d42eb0d86a7fdd3c4e5669c46376d0d4c041da5adb3f5d0e3ccbe9f369ef54`。所有 RVA 均来自此内层 ELF。原始二进制仅在私有工作环境解密、反汇编，未提交仓库。

## 1. 条件入口已证明

此前 [H 的管道收发](12.5.5-secneo-h-pipe-result-chain.md) 已证实：默认 `--flags 0` 让子进程 `H.a(0)` 提取 `/proc/self/status` 的 `TracerPid`，通过 `writeUTF` 回传；主端 `readUTF` 后执行 `atoi`。

[配置初始化](12.5.5-secneo-h-guard-config-alias.md) 验证 `0x12a5bc` 的初始值为 `13`，bit0 为 1。但这是静态初始化值，设备实时状态未采样。

只有同时满足数值结果大于或等于 1，以及这个 bit0 为 1，原生线程才会从 `0x5ae54` 进入 `0x5af18`。其后续流程为：

- `0x5af34` 调用 `0x2616c`，若返回零，跳到 `0x5af6c` 清理。
- `0x5af44` 调用 `0x2682c`，若结果非零，跳到 `0x5af6c`。
- 满足前两个条件后，`0x5af64` 设置第二参数 `w1=1`，`0x5af68` 调用 `0x26bc0`；第三参数由 `0x5af50..0x5af5c` 的指令构成。

这证明 `0x26bc0` 处于该**有前置条件的可达分支**，并没有证明它在用户手机上实际执行。

## 2. `0x26bc0` 的原版文件读写行为

这次从原版反汇编逐条复核，确认其主体包含：

| 原版地址 | 直接调用/行为 |
| --- | --- |
| `0x26d30` | `access@plt` |
| `0x26d44`、`0x26d5c` | `fopen@plt` |
| `0x26d68`、`0x26d70` | `fileno@plt`、`flock@plt` |
| `0x26d94` | `fseek@plt` |
| `0x26e04`、`0x26e44` | `fgets@plt` |
| `0x26ebc`、`0x26eec` | 内部 `0x273d8` 和 `0x27524`，参与数据准备与转换 |
| `0x26f5c`、`0x26f78–0x26f8c` | 字节逐个比较，失败时回到下一行处理 |
| `0x2707c`、`0x270ec` | 内部 `0x27ee0`、`0x27d50`，参与转换或长度检验 |
| **`0x27130`** | **`fseek@plt`** |
| **`0x27144`** | **`fwrite@plt`** |
| **`0x2714c`** | **`fflush@plt`** |
| `0x27154` | `fclose@plt` |

后续原版字符表和跳转表核验已经确认：`0x2616c(1)` 构造的记录键为 **`root`**；`0x2682c` 和 `0x26bc0` 各自独立构造的文件名均为 **`envc.push`**，通过运行时前缀路径指针槽 `0x128010` 拼接实际路径。读取模式 `r`，缺失时创建模式 `w+`，更新模式 `r+`。完整绝对路径与写入后的设备实际字节未得到取证。文件是否修改还取决于前面的存在性、锁定、读取、比较及转换条件。详见[root 记录专项审计](12.5.5-secneo-h-envc-push-root-record.md)。

## 3. 第二个帮助函数同样读取文件

`0x2682c` 自身在 `0x26930` 调用 `fopen`，在 `0x269b0` 调用 `fgets`，存在逐行处理。原版已证实它和后续更新函数均访问同名的 `envc.push`，并使用同一运行时目录前缀。查询函数会识别 `root=` 的逻辑记录前缀，将状态数字与后续十六进制标识分别解析；状态非零时跳过相应更新。

## 4. 对后续研究的影响

现有证据完整贯通至：原版 SecNeo `TracerPid` 检查结果 → 父端数值判断 → 运行时字段 bit0 分流 → `0x2616c/0x2682c` 条件 → `0x26bc0` 潜在文件修改。

**仍未证明**文件的最终绝对路径、修改前后字节、目标设备的真实执行次数，以及 `DECMsgDialog`、`DeviceEnvironmentCheck.startCheck()` 或此前 `SIGSEGV 0x978/0x97c` 与此链的因果关系。不能据此认定它向用户弹出 DEC 警告。

