# 中国移动 12.5.5：SecNeo H 辅助进程与管道 IPC 的证据边界

核验日期：2026-10-24。仅依据原始 APK 的已验证 ARM64 指令、同一轮 `CNMB-after-reboot.txt` 的设备 Logcat 和公开仓库中已复核的原版代码报告。本文件不包含商业客户端二进制、完整 Logcat、FD 指向路径或私有内容。

## 原版代码已证明的管道传参

受保护内层 `libDexHelper.so` 中，线程入口 `0x59700`（由原版 `.eh_frame` 确定边界）包含：

- `0x5A3D0`：调用 `pipe@plt`。
- `0x5A418` 和 `0x5A4C4`：两次 `fork@plt`，属于同一个工作线程的控制流。
- `0x5A404`：将**运行时管道写端 FD** 格式化为十进制字符串；`0x5A40C` 复制该字符串。
- `0x5A710`：调用 `execl("/system/bin/app_process", "/system/bin/app_process", "/system/bin", "--nice-name=zygote", <入口类>, "--write-fd", <FD字符串>, "--flags", "0", NULL)`。原版默认入口类由独立指令数据流恢复为 `com/secneo/apkwrapper/H`，且运行时可覆盖。

详见[线程和原版参数数据流](12.5.5-inner-app-process-argv-thread-chain.md)。这一序列直接确认**原生进程启动路径向 Java 主类传递一个可写端 FD**。目前尚未恢复 `H` 的对应参数读取、写入内容、父端的读取及消费函数，不能据此断言管道携带 Root/DEC 检测结果。

对整个 1719 行日志进行逐 PID 检索，**该日志没有提供 PID 8714 的管道 FD、父进程的读端、`read`/`write` 系统调用或实际交换的数据**。同样，`Shutting down VM` 不能用作进程实际死亡的精确时间。故静态 `--write-fd` 和运行时 `H` 入口相互印证一个进程启动机制，但 IPC 通路还缺少动态对应。

## 新实验：只读取证共享管道 FD

新增 [`experiments/capture_shared_pipes.py`](../experiments/capture_shared_pipes.py)。对当前目标包名**精确匹配**的进程定期查询 `ps -A -o PID,PPID,NAME`；在 Root 权限下，只检查它们的 `/proc/PID/fd` 软链接中类型为 `pipe:[inode]` 的项目及 `/proc/PID/fdinfo/FD` 的八进制访问标志，不读取 FD 的数据，也不注入 App。

程序仅报告**同一时刻两个及以上目标 PID** 持有相同匿名管道 inode 的情况，记录每一方的 PID、FD 编号、瞬时 PPID 和读/写访问模式。管道 inode 在导出 JSON 时替换为单次采集内部稳定的 `pipe_1`、`pipe_2`；完整的软链接目标、应用命令行、系统套接字、文件内容均不会输出。

先确认 ADB 已连接、Frida 服务端没有运行；此命令会重启应用，**不会清除应用数据**：

```powershell
python .\experiments\capture_shared_pipes.py --launch --seconds 18 --poll-seconds 0.2 --output .\shared-pipes-local.json
```

如果 App 已运行，去掉 `--launch` 即可纯观察。设备必须已经授予 `su` Root 权限；程序在重启前检查 Root 可用，权限不足则停止。命令的实际轮询频率受 ADB/Root 调用耗时限制，设定 `0.2` 秒并不保证每 200 毫秒完成完整采样。

**结果解读：**

- 出现相同 `pipe_N` 且一个 PID 的 `access_mode=write`、另一个 `access_mode=read`：直接证明采样瞬间存在可通信的管道两端。若同时观察到与 `H` 对应的 PID，再结合其当次 AndroidRuntime 日志可将 IPC 候选范围收窄到具体进程。
- 同一 inode 在两个 PID 下均为 `write` 或均为 `read`：证明描述符指向同一管道，但无法据此恢复数据流向。
- 没有共享管道：只能说明采样未观察到目标进程间的共享 FD。双重 fork、FD 关闭及 PID 快速重托管可能使真正的通信时段非常短；另一端还可能属于包名不同的临时进程。
- 读写端匹配本身**无法证明**进程亲缘关系、数据已经传送、消息语义或 DEC 因果。还需要原版 `H` 字节码和父端 native `read` 的调用链。

输入/输出都属于私人运行时材料，`shared-pipes-local.json` 应当仅保存在本地，公开仓库只保留已脱敏的结论；该工具仅通过合成测试，**尚未在目标设备实测**。
